# Cliniverse AI — Brand & Shell Direction v1

## Brand hierarchy

**NeuraOps** — company and shared AI workflow platform.

**Cliniverse AI** — core healthcare vertical.

Recommended product lockup:
**Cliniverse AI — Healthcare Intelligence by NeuraOps**

## Design principles

- Enterprise, calm, credible, clinical.
- Shared NeuraOps visual language; Cliniverse receives a restrained healthcare accent.
- Dark/deep-navy product environment.
- Primary action is blue.
- Violet supports intelligent/AI states.
- Teal may be retained only as a restrained Cliniverse healthcare accent.
- Gold is semantic only: priority, attention, or exceptional operational states.
- Green = success/resolved.
- Red = critical/error.
- Avoid generic AI brains, robots, holograms, sci-fi glass tunnels, excessive gradients, and decorative complexity.

## Information architecture

### Primary navigation
- Home
- Care Operations
- Clinical Intelligence
- Clinical Tools
- Academy

### Secondary / role-gated
- Admin
- Integrations
- Settings

## Home priorities

The home view should answer only four questions:
1. What needs attention now?
2. What follow-up is due?
3. What is escalated to a human?
4. What changed recently?

Do not expose the full capability library on the home screen.

## Care Operations

Primary objects:
- Follow-up item
- Patient/workflow context
- Priority state
- Escalation
- Owner
- Timeline
- Resolution state

## Clinical Intelligence

Primary objects:
- Evidence
- Context assistant
- Similar context/cases
- Dissent/uncertainty
- Human review prompt

## Clinical Tools

Preserve the existing tool library but group it into categories. Tools are secondary capabilities, not the product's top-level identity.

## Academy

Preserve simulation, MCQs, board preparation, Code Blue/BLS/ACLS and other education assets under a dedicated Academy area.

## Responsive behavior

Desktop: persistent left sidebar with compact top utility bar.
Mobile: bottom navigation for the five primary areas, with secondary items in an overflow/menu sheet.

## v0 usage

Use v0 for:
- shell prototypes
- dashboard composition
- responsive layouts
- component variants
- campaign/healthcare landing pages

Do not use v0 to invent:
- clinical logic
- auth/security rules
- FHIR transactions
- medical confidence scoring
- database authorization
- production PHI workflows
